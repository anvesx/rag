# ingestion module
Goal: connector to index pipeline. `createIngestion({runtime, indexService, connectorFor, tokenFor})` resolves the connector and credential per tenant (unknown tenant: IngestionError UNKNOWN_TENANT), runs connector-runtime runOnce with a sink that calls index-service apply(event); returns {runOnce(tenantId)} with counts {emitted, indexed, failed, failures: {address, error}[], quarantined}. A failing document does not block others, is retried up to maxAttempts then quarantined, and deletes still run. Runs per tenant are serialised. Acceptance: first run indexes all docs, rerun indexes none, modified file reindexes one, index failure is reported in failures and retried, ACL change reindexes, failing doc does not block others, wrong-tenant connector rejected, deleted file tombstones. Addendum: optional `known?(tenantId): Iterable<string> | Promise<Iterable<string>>` returns pointer ids (docId) the index already holds; once a run has listed every page from the start, they are merged into the known set before the delete pass, so docs deleted while the process was down are tombstoned. Incomplete listings tombstone nothing; duplicates are harmless; a throwing seed rejects the run. Requires services/index-service merged first. Each changed document is fetched once: the sink passes the fetched text and its hash to `apply` as `content`, so index-service does not re-fetch.

Rules: package modules/NAME, name @rag/NAME, may depend on @rag/* services and features (never apps, never another module). Compose existing packages; build no new core logic. TDD: failing tests first in tests/{unit,integration}. Files <=80 lines, folders <=5 files (README exempt), src/ tests/ README.md in the package plus README in each src subfolder. ESM TypeScript, vitest 5. Copy config shape from services/query-service. Gate before reporting: pnpm structure, pnpm exec biome check ., pnpm deps, package test+typecheck, all exit 0 (explicit codes, no pipes). Commit on your branch, conventional message, no attribution.

Addendum (hardening): a reap guard refuses delete passes that look like mistakes. An empty listing (no ids seen) while the index holds known docs is always refused ("empty-listing"); otherwise, once at least 10 docs are known, deleting more than 50% of them is refused ("too-many"). Refused passes are reported as `counts.reapSkipped` rather than tombstoning. Passing `reapGuard: false` disables the guard; thresholds default to `minDocs: 10` and `maxFraction: 0.5`.
